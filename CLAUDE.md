## What this is

A **federated Flutter plugin** for on-device receipt image acquisition — crop, orientation normalization, JPEG compression, EXIF extraction, and raw-string OCR — on iOS and Android.
The plugin returns **image primitives only**.
Receipt domain parsing (store/amount/date), upload, cloud OCR, and duplicate detection belong to the consuming app, not here.

The repo is both a **Dart pub workspace** (`workspace:` in the root `pubspec.yaml`, requires Dart SDK ^3.12) and a **Melos workspace**. Pub resolves a single shared lockfile; Melos runs the scripts below.

## Commands

Run from the repo root unless noted.

```bash
melos bootstrap                 # resolve + link all workspace packages (run first)
melos run analyze               # dart analyze across every package
melos run test                  # flutter test in every package that has test/
melos run test:ci               # same, with --coverage --concurrency 4
melos run format                # dart fix --apply + dart format --line-length 120
melos run format:ci             # format check only (--set-exit-if-changed)
melos run generate              # regenerate Pigeon contracts (see Transport)
trunk fmt && trunk check        # format + lint all NON-Dart files
```

Run the example app: `cd flutter_receipt_scanner/example && flutter run`.

Run one package's tests, or a single test:

```bash
cd flutter_receipt_scanner && flutter test                                   # one package
cd flutter_receipt_scanner && flutter test test/ocr_floor_test.dart          # one file
cd flutter_receipt_scanner && flutter test --plain-name "applies the floor"  # one test by name
```

## Architecture

### Package layout and responsibility boundary

| Package                                      | Owns                                                                                       |
| -------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `flutter_receipt_scanner`                    | App-facing API: `scan()` and the Dart-side **OCR-floor acceptance gate**.                  |
| `flutter_receipt_scanner_platform_interface` | Abstract `FlutterReceiptScannerPlatform` + hand-written public models (`lib/src/models/`). |
| `flutter_receipt_scanner_ios`                | iOS impl (VisionKit document scanner + Vision OCR), native code in `ios/`.                 |
| `flutter_receipt_scanner_android`            | Android impl (GMS document scanner + ML Kit OCR), native code in `android/`.               |

The hard boundary: native packages produce acquired/cropped image, orientation-normalized JPEG, EXIF, and raw OCR string. The **OCR-floor gate** — the heuristic deciding whether an image clears the minimum OCR signal to count as a receipt — lives only in the Dart `flutter_receipt_scanner` package (`lib/src/ocr_floor.dart`). Keep receipt domain logic out of native code.

### Call flow

```log
scan() [app pkg]
  → FlutterReceiptScannerPlatform.instance.scan(options) [platform interface]
  → platform pkg maps ScanReceiptOptions → *Wire, calls Pigeon ReceiptScannerApi (@HostApi, @async)
  → native scan/crop/OCR → *Wire result
  → platform pkg maps *Wire → public models
  → applyOcrFloor(...) [app pkg] partitions images vs rejectedImages
```

The platform packages `extend` (never `implement`) `FlutterReceiptScannerPlatform` so new interface methods get a default and don't break existing platforms. With no registered platform, `scan()` throws `UnsupportedError`.

### OCR-floor gate semantics (`ocr_floor.dart`)

- `deriveQuality()` computes trimmed char count + non-empty line count from joined OCR text; native confidence is passed through.
- An image passes when `textLength ≥ minTextLength (12)` **and** `lineCount ≥ minLines (2)` **and** (confidence absent, **or** confidence ≥ `minConfidence`).
- **Absent confidence never gates** — a field that wasn't produced (OCR disabled, no text) is treated as satisfied. `minConfidence` defaults to `0` and is reporting-only until cross-platform distributions are validated comparable.
- Non-success statuses pass through untouched. If every image falls below the floor, status becomes `ScanStatus.rejected` and images move to `rejectedImages`.

### Transport: Pigeon

The host↔native contract is code-generated by Pigeon into `*.g.dart` / `Messages.g.swift` / `Messages.g.kt`.
Note: the schema is **duplicated per platform package** — `flutter_receipt_scanner_ios/pigeons/messages.dart` and `flutter_receipt_scanner_android/pigeons/messages.dart` are identical except for the `swiftOut`/`kotlinOut` output config. Edit **both** in lockstep when changing the wire contract.
`melos run generate` runs pigeon in each package tagged `depends-on: pigeon`.

**Never hand-edit generated output** (`*.g.dart`, `Messages.g.swift`, `Messages.g.kt`) — change the `pigeons/messages.dart` schema and regenerate.

Wire types are `*Wire` (e.g. `ScanOptionsWire`, `ReceiptImageWire`); public models are the un-suffixed classes in the platform interface. The platform packages hold the mapping in both directions.

## Conventions

- **Dart is owned by Flutter/Melos, not trunk.** trunk disables the `dart` linter on purpose (`.trunk/trunk.yaml`). Dart follows `very_good_analysis`, formatted at `--line-length 120`, 2-space indent. Kotlin (ktlint), Swift (swiftformat), YAML, Markdown, GitHub Actions, and security scanners are owned by trunk.
- Platform baselines: **iOS deployment target 16.0**, **Android minSdk 24**.
- Commit messages: Conventional Commits with gitmoji (`feat: ✨ ...`, `docs: 📝 ...`). Messages and identifiers in English; **Korean comments and user-facing strings are intentional — do not translate them.**
- Output `file://` JPEG URIs are valid only until the next `scan()` call and do not survive app restarts (OS clears the cache dir).
